# AI Investment Plan Copilot User Flow

# 1. Experience Architecture

제품 전체를 챗봇으로 만들지 않는다.

사용자의 생각을 이해하고 조건을 확인하는 구간에서는
대화형 인터페이스를 사용한다.

숫자, 시장 데이터, 시뮬레이션 결과,
조정안 비교와 최종 승인은 구조화된 화면으로 제공한다.

```text
시작 안내
→ Guided Conversation
→ 현재 계획 확인
→ Agent 실행 승인
→ 실제 데이터 분석
→ 분석 워크스페이스
→ 자연어 수정 요청
→ 조정안 비교
→ 최종 승인
→ Historical Agent Replay
```

## 용어: Historical Condition Replay (과거 조건 시뮬레이션)

이 제품의 분석은 **정식 백테스트가 아니다.** 최근 1년 가격에 현재 조건을 적용해
**조건 발생 시점**과 **모의 실행 이벤트**를 확인하는 것이다.

```text
사용자가 입력한 평균 매수가를 고정 기준으로 사용해
최근 가격에서 조건 발생 시점을 확인합니다.
실제 체결 수량, 환율, 평균 매수가 변화는 반영하지 않습니다.
```

MVP 가 구현하지 않는 것:

- 실제 주식 수량
- 환율 변환
- 동적 평균 매수가(매수에 따른 평단 갱신)
- 실제 체결
- 투자 수익률

따라서 다음 표현을 쓰지 않는다: "이 전략을 1년 동안 실행했다면", "실제 투자 성과",
"백테스트 수익률", "실제 매수 결과", "수익성 검증".

대신 쓰는 표현: "최근 1년 가격에 현재 조건을 적용하면", "조건 발생 시점",
"모의 실행 이벤트", "과거 조건 시뮬레이션".

## 인터페이스 역할

| 인터페이스 | 역할 |
|---|---|
| 대화 | 생각과 제약을 확인 |
| 현재 계획 카드 | AI가 이해한 내용을 검증 |
| 작업 로그 | Agent가 사용한 도구와 진행 상태 표시 |
| 차트 | 과거 시장에서 조건이 발생한 시점 표시 |
| 지표 | 조건의 빈도와 자금 부담 설명 |
| 비교표 | 기존 계획과 조정안의 차이 확인 |
| 타임라인 | 최종 계획이 어떻게 작동하는지 재생 |
| 사용자 승인 | 최종 결정권 보장 |

## 6.2 AI 응답 원칙

AI는 사용자의 입력을 먼저 요약한다.


그다음 **가장 우선순위가 높은 질문 하나만** 묻는다.

```text

```

### 빠른 선택

```text
매주 30,000원
매주 50,000원
매달 200,000원
직접 입력
```

---

## 6.3 질문 우선순위

AI는 이미 확인한 값은 다시 묻지 않는다.

필수 질문 순서:

1. 종목
2. 정기 매수 주기와 금액
3. 추가 매수 기준
4. 하락률
5. 추가 매수 금액
6. 기준 가격 입력
7. 사용자가 언급한 경우 월 최대 예산

다음 항목은 초기 대화에서 강제로 묻지 않는다.

- 추가 매수 최대 횟수
- 재검토 기준
- 정기 검토 주기

이 항목은 시뮬레이션 후
위험을 확인한 상황에서 설정하게 한다.

## 6.5 현재 계획 카드

대화 상단에 compact card로 고정한다.

### 기본 상태

```text
현재 계획  3/6 완료
```

### 펼친 상태

```text
Apple Inc. · AAPL

정기 매수
매주 50,000원

추가 매수
평균 매수가보다 3% 하락 시 20,000원

평균 매수가
320 USD

월 최대 예산
확인하지 않음
```

## 카드 동작

- 카드 전체를 누르면 펼쳐진다.
- 각 값에 `수정` 액션을 제공한다.
- 수정하면 관련 시뮬레이션 결과를 무효화한다.
- 미확정 값은 `확인 필요`로 표시한다.
- AI가 이해한 내용과 사용자의 원문을 구분한다.

---

## 6.6 질문 피로 방지

- 최대 필수 질문은 5개를 목표로 한다.
- 한 입력에서 여러 조건이 확인되면 질문 수를 줄인다.
- 사용자가 전체 계획을 한 문장으로 입력하면 이미 있는 값은 건너뛴다.
- 안전장치는 시뮬레이션 이전에 모두 묻지 않는다.
- 질문마다 이유를 1문장 이내로 설명한다.
- 사용자는 언제든 `현재 계획 확인`을 선택할 수 있다.

---

## 6.7 대화 입력 규칙

- Quick Reply와 직접 입력을 모두 제공한다.
- 텍스트 입력은 항상 사용 가능하다.
- 사용자가 이전 답을 바꾸겠다고 하면 수정 의도로 인식한다.
- 모호한 숫자는 추정하지 않는다.
- 사용자가 투자 종목 추천을 요청하면 지원 범위를 안내한다.

### 종목 추천 요청 예시

```text

```

# 14. Conversation Rules

## CR-01. 한 번에 하나의 핵심 질문

동시에 여러 값을 요구하지 않는다.

단, 주기와 금액처럼 하나의 선택지로 자연스럽게 묶이는 값은
하나의 Quick Reply로 받을 수 있다.

## CR-02. 이미 확인한 내용은 다시 묻지 않는다

사용자 입력에서 확인된 필드는 질문에서 제외한다.

## CR-03. 숫자를 추정하지 않는다

다음 표현은 질문으로 전환한다.

- 조금
- 많이
- 적당히
- 천천히
- 자주
- 떨어지면
- 오르면

## CR-04. 질문 이유를 설명한다

이유는 1문장 이내로 제공한다.

## CR-05. 대화 결과를 즉시 구조화한다

각 답변이 현재 계획 카드에 바로 반영되어야 한다.

## CR-06. 수정 가능해야 한다

사용자는 채팅을 되돌리지 않고
계획 카드에서 직접 값을 변경할 수 있어야 한다.

## CR-07. AI 범위를 명확히 한다

AI는:

- 종목 추천을 하지 않는다.
- 수익률을 예측하지 않는다.
- 실제 주문을 실행하지 않는다.
- 하나의 최적안을 강요하지 않는다.

# 17. Prototype Completion Criteria

다음 화면 이동만 구현해서는 완료로 보지 않는다.

## 대화

- 막연한 입력을 실제 Claude가 구조화한다.
- 이미 확인된 값을 다시 묻지 않는다.
- 누락된 값은 질문으로 이어진다.
- 답변이 현재 계획 카드에 반영된다.
- 카드에서 수정하면 상태가 함께 변경된다.

## 데이터

- 실제 Market API에서 종목과 현재 데이터를 조회한다.
- 최근 1년 일별 데이터를 조회한다.
- 데이터 기준 시각과 출처를 표시한다.

## 시뮬레이션

- TypeScript가 정기 매수 이벤트를 계산한다.
- TypeScript가 평균 매수가를 계산한다.
- TypeScript가 추가 매수 조건을 계산한다.
- TypeScript가 월 투자 금액을 계산한다.
- TypeScript가 예산 초과와 재검토 이벤트를 계산한다.

## AI Review

- AI가 코드 계산 결과를 설명한다.
- 계산되지 않은 숫자를 새로 생성하지 않는다.
- 계획의 장점과 위험을 함께 설명한다.
- 각 위험이 사용한 지표와 연결된다.

## Revision

- 사용자의 자연어 수정 요청을 구조화한다.
- 조정안 2개가 실제 코드로 다시 계산된다.
- 조정안이 사용자 제약을 만족한다.
- 기존 계획과 조정안의 결과가 달라진다.

## Human Control

- AI가 최적안을 자동 선택하지 않는다.
- 사용자가 직접 계획을 선택한다.
- 최종 승인 이후에만 모의 실행된다.
- 실제 주문은 실행되지 않는다.

## Replay

- 최종 계획의 과거 이벤트가 시간순으로 표시된다.
- 실행된 조건과 제한으로 차단된 조건을 구분한다.
- 재검토 조건 발생을 보여준다.
