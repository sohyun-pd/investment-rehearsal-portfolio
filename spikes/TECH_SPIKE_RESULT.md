## 1. LLM 파서 (Anthropic, 실제 호출)

- **provider / 모델**: `anthropic` / `claude-sonnet-5` (`.env.local` 의 `LLM_MODEL`)
- **방식**: 공식 `@anthropic-ai/sdk`, 구조화 출력(`output_config.format` = json_schema), `effort: low`
- **실제 호출 성공 여부**: ✅ 3건 모두 200 응답, 유효한 구조화 JSON 반환
- **응답 시간** (2026-07-28 실측):

| 케이스 | 입력 | 응답시간 |
|--------|------|----------|
| buy-simple | "삼성전자 10주 시장가로 사줘" | 5522ms |
| sell-limit | "애플 5주를 200달러에 팔아" | 2586ms |
| ambiguous | "그거 좀 정리해줘" | 3705ms |

- **기대값 일치**: 2/3
  - `sell-limit`, `ambiguous`: 완전 일치
  - `buy-simple`: `action/수량/시장가/종목명`은 정확했으나 **종목코드(005930)를 비움**.
    → 시스템 프롬프트의 "확실하지 않으면 null" 지시를 따른 정상 동작.
    한국 종목명→코드 매핑은 LLM 단독으로 불충분 → **종목 마스터/검색 API 연동 필요**(발견사항).
- **무료 티어/비용 한계**: Anthropic API는 유료(무료 티어 없음). claude-sonnet-5 기준 과금.
  파싱 1건당 수천 토큰 미만이라 단가 자체는 낮으나, 실시간 지시 파싱은 호출량×단가 관리 필요.
- **보안**: API 키는 출력/로그에 남기지 않음(에러도 `err.message` 만 출력). 키는 `.env.local` 에만.

## 2. 시장 데이터 (Finnhub, 실제 호출)

- **provider**: `finnhub` (미국 주식 대상)
- **실제 호출 성공 여부**: ✅ 검색 + 시세 조회 모두 성공
- **검색 결과 예** ("apple"): AAPL(Apple Inc), APLE, MLP, PAPL, AAPI — 미국 공통주 필터링 적용
- **시세 예 (AAPL)**: 현재가 336.91 USD / 전일 종가 333.02 USD / 전일 대비 **+1.17%** / 기준시각 **2026-07-27T20:00:00Z**
- **응답 시간** (2026-07-28 실측): 검색 482ms, 시세 775ms
- **데이터 시점**: 조회 시각(2026-07-28) 기준 직전 미국 정규장 마감(2026-07-27 20:00 UTC = 16:00 ET). 실시간이 아닌 **마감/지연 데이터**로 보임.
- **무료 티어 한계**:
  - Finnhub 무료: 분당 60 API calls. 미국 주식 위주(일부 해외/실시간은 유료).
  - 정규장 실시간 시세는 제한될 수 있음 → 지연/마감가 기준.
- **정책**: 키 없음/호출 실패 시 **mock 폴백하지 않고 명시적 오류** 반환.

## 핵심 설계 결정

1. **어댑터(Provider) 교체 구조** — 공통 인터페이스만 고정, 구현은 환경변수로 교체.
   - LLM: `LlmParser` → `LLM_PROVIDER` (`mock` | `anthropic`; openai 자리 준비)
   - Market: `MarketDataProvider` + 정규화 `Quote`/`SymbolMatch` → `MARKET_PROVIDER` (`mock` | `finnhub` | `alphavantage`)
2. **Mock 우선** — 키 없이 `mock` 으로 파이프라인/스키마 검증 가능. 키 넣고 provider 바꾸면 실제 호출.
3. **키 격리** — 실제 키는 `.env.local` 에만(`.gitignore` 제외). 로더(`spikes/env.ts`)가 `.env.local` 우선 로드.
   - 주의: `dotenv/config` 기본값은 `.env` 만 로드 → `.env.local` 명시 로드 필요(검증 중 발견해 수정).

## 3. LLM 조건부/정기 전략 파싱 (Anthropic, 1회성 추가 검증)

> `단순 주문 파싱`을 넘어 `조건부 전략 MVP`가 가능한지 확인. 스크립트: `spike:strategy`.
> 스키마: 여러 규칙(rules[]) — 정기/조건부 매수·매도, 기준가(평균매수가/현재가/직전종가) 명시.

- **실제 호출 성공 여부**: ✅ 3문장 모두 구조화 성공 (claude-sonnet-5)
- **응답 시간**: 7960ms / 3524ms / 5519ms (단순 주문보다 김 → **최대 ~8초** 고려 필요)
- **확인 기준 4종 결과 (6/6 통과)**:

| 문장 | 확인 기준 | 결과 |
|------|-----------|------|
| ① 애플 매주 5만원 + 평균매수가 -3% 시 2만원 | 정기매수 vs 조건부매수 구분 | ✅ recurring_buy + conditional_buy |
| ① | 기준가 = 평균매수가 명시 | ✅ `average_cost` |
| ② 엔비디아 +10% 절반 매도 / -5% 3만원 매수 | 매수·매도 조건 동시 구조화 | ✅ conditional_sell + conditional_buy |
| ② | 기준가 명시 | ✅ `current_price` |
| ③ 테슬라 조금씩 모으다 많이 오르면 일부 매도 | 추가 질문 요구 | ✅ needsClarification + 질문 3개 |
| ③ | 숫자 지어내지 않음 | ✅ 임계치/금액/비율 모두 null |

- **해석**: 조건부 전략 MVP는 기술적으로 성립. 특히 ③에서 상승률/금액/매도비율을 **지어내지 않고** 되물음 → 신뢰성 확보.
- **발견사항**: 기준가 표현("평균 매수가보다" vs "오르면")을 `average_cost`/`current_price` 로 올바르게 구분.
  제품에서는 이 기준가 종류를 **사용자에게 명시 확인**시키는 UX가 필요(오해 방지).

## 제품 설계에 즉시 반영할 제약 (검증으로 확정)

1. **응답 시간 2.6~8초 → "즉시 결과"처럼 보이면 안 됨.** 진행 상태 단계 표시 필수:
   `요청 해석 중 → 종목·조건 확인 중 → 실행 조건 생성 완료`
2. **Finnhub 무료 = 실시간 아님(지연/마감 시세).** 시세 화면에 반드시 명시:
   `직전 미국 정규장 마감 기준 / 2026.07.28 05:00 KST / 지연 시세`
   → 타임스탬프는 부가정보가 아니라 **핵심 신뢰 장치**. AI 결과 시점과 시세 기준 시점이 다르면 오판 위험.
3. **오류 상태를 제품에서 명시.** 실패 시 mock 폴백 금지, 명시적 오류 노출(스파이크에서 이미 이 정책 적용).

## 발견사항 / 리스크

- **한국 종목명→코드 매핑**: LLM 단독으로는 코드(예: 005930)를 신뢰성 있게 못 냄. 종목 마스터 or 검색 API 필요.
- **Finnhub 실시간성**: 무료 티어는 지연/마감가. 실시간 필요 시 유료 or 국내 종목은 다른 소스 검토.
- **국내(KRX) 종목**: Finnhub 미국 위주. 한국 주식 시세/검색은 별도 provider 필요(어댑터 추가로 대응 가능).
- **비용**: Anthropic 유료. 파싱 호출량 증가 시 단가×호출수 관리 및 캐싱/배치 검토.
